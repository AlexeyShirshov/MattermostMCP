# Coding Conventions

C# / SQL / Общее — расшифровка с фото. Многоточие (…) отмечает текст, обрезанный краем фотографии.

## C#

1. **Primary constructor для класса**
   - используется всегда по возможности
   - параметры только для инициализации членов
2. **Pattern matching**
   - обязательно используется для проверки на null вместо операторов equality
   - в остальных случаях если подходит по логике алгоритма
3. **Блоки кода отделяются друг от друга пустой строкой**, например
   - класс
   - объявление членов класса
   - метод, свойство
4. **При именовании придерживаемся** [https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/coding-style/identifier-names](https://learn.microsoft.com/en-us/dotnet/csharp/fundamentals/coding-style/identifier-names)
   - приватные члены начинаются с подчёркивания - implemented
   - константы прописными буквами - doesn't violate
   - асинхронные методы снабжаются постфиксом Async только если есть синхронный аналог - doesn't violate
   - CancellationToken называем полностью, если имя параметра не пришло из базового класса, также это правило не распространяется…
   - наименование сущностей согласно конвенции по микросервисам в единственном числе, акронимы в стиле MS (XML -> Xml) - doesn't violate
   - имена таблиц – название сущности во множественном числе согласно правилам английского языка – doesn't violate
   - UPPER CASE SQL - doesn't violate
   - рекомендуемая длина строки 100 символов
5. **Расположение репозиториев: интерфейсы в домене**
6. **Пространства имён**
   - рекомендовано ограничиться 4-5 уровнями вложенности, где первые 3 фиксированы на уровне сервиса, например Ozon.MZCore.Re…
   - структура папок внутри проекта не обязательно должна совпадать со структурой пространства имён
7. **Предпочитаемый механизм реализации http-ручек является Minimal API**
8. **Nullable по умолчанию всегда включен**
9. **Логирование на уровне Information не должно происходить в цикле обработчиков очереди, а также в обработчике, если RPS более 1000.**
10. **Декларация массивов** - var documentIds = new MetazonDocumentId[] { new (1), new (2), new (3) }; => MetazonDocumentId[] documentIds = [new (1), new (2), new (3)];
11. **Таски без авейтов. Если есть возможность, возвращать Task напрямую без await**
12. **Linq vs Foreach. Предпочитайте один foreach нескольким вызовам Linq**
13. **DateTime vs DateTimeOffset** MZCore №41 05.08-16.08. Используем DateTimeOffset по умолчанию (согласно рекомендациям Microsoft https://…
14. **Использование CancellationToken. Используем ThrowIfCancellationRequested. Если метод особо чувствительный к производительности, то ра…**
15. **Методы логирования должны начинаться с префикса Log**
16. **Паттерн матчинг в выражении if/while, приводящий к нескольким операциям в одной строчке, увеличивает сложность, поэтому должно исп…**
17. **Вложенные выражения vs if (...) continue/break/return. Предпочтение отдаётся раннему выходу из ф-ции/цикла**
18. **Использование static лямбда везде где возможно**
19. **Включаем в IDE форматирование при сохранении**
20. **Не использовать в тестах проверки на то, что exception не выбросился, если есть другие asserts**
21. **Использование tuple. Именуем члены tuple с большой буквы. Имена должны быть. Используем tuples только для непубличных методов**
22. **Возвращаем наиболее специфичный интерфейс для коллекции, а принимаем наименее специфичный. Избегаем вызова ToArray/ToList перед…**
23. **Не использовать Arg.Is проверку на равенство объектов без необходимости.** [https://nsubstitute.github.io/help/argument-matchers/#matching-a…](https://nsubstitute.github.io/help/argument-matchers/)
24. **ToArray vs ToList. Используем ToArray, если не нужно добавлять/удалять элементы из коллекции**
25. **Документируем свойства бизнес сущностей, а также большие сложные методы**
26. **Инициализация Dictionary. Используем квадратные скобки и присваивание**
27. **Используем деконструкцию KeyValuePair для Dictionary в foreach**
28. **Регистрация сервисов. Отказываемся от Registrar и используем ServiceCollectionExtensions постфикс**
29. **Комментарии оставляем либо на русском, либо на английском**
30. **Логи пишем на английском**
31. **Используем records для доменных сущностей и dto, если не нужно менять свойства**
32. **Добавляем sealed в dto**
33. *Мы должны использовать тест для проверки покрытия всех методов репозиториев / definitions тестами.*

## SQL

1. **Именование миграций (по дате или инкремент лонга). Именуем используя целые числа по возрастанию**
2. **count(\*) vs count(1). Используем count(\*)**
3. **EXISTS vs tuples. Exists в целом должен быть производительнее, поэтому желательно использовать его**
4. **Audit Tables vs Logs. Используем логи для аудита, если нет бизнес требований**
5. **Использование кортежей с IN/EXISTS вместо JOIN в ClickHouse**
6. **Название primary key колонки в бд - "id". В других таблицах ссылаемся на id как на "table_name_id"**
7. **Использовать условие IF EXISTS при переименовании колонки в ClickHouse. Иначе можно получить ошибку: Wrong column name. Cannot find column…**
8. **Не добавляем params возле columns в definitions. Оставляем params в методе либо репозитории**
9. **Форматирование SQL**
   - multiline select, update: запятые ставим в начале строки при перечислении параметров. SET ставим в конце строки;
   - join: ON ставим в конце строки;
   - insert: запятые ставим в начале строки;
   - CTE: WITH на отдельной строке;
   - raw string literals (множественные кавычки) для вставки sql в .cs файл.
10. **Скрипты с фиксами данных кладём в путь аналогичный:** migrations/support/SDMT_####/1_datafix.sql
11. *В новых проектах в definitions не используем плейсхолдеры для колонок.*
12. *Используем осмысленные алиасы.*
